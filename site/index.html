Install the repo, then run the demo.

Everything needed to try FlowDiff is in the public repository. Clone it, run the included comparison, then bring the same shape into a real UX review.

  1. 01

    Install from GitHub

    Clone the repo that contains the plugin manifest, local server, demo, and tests.

    git clone https://github.com/henryvn27/flowdiff.git cd flowdiff
  2. 02

    Run the included demo

    Generate a Markdown parity report from the synthetic Baseline and Candidate traces.

    python3 server.py --demo --format markdown
  3. 03

    Use it in the review

    After testing two apps, pass in sanitized outcomes and let the report name the next check.

    Ask Codex Compare these sanitized dictation UX traces.

For a clean local check, run python3 -m unittest discover -s tests -v.

Use it in the review.

FlowDiff is for the handoff between trying a product and deciding what to fix. The input stays small so the output stays reviewable.

  1. 01

    Record outcomes

    Mark activation, feedback, insertion, settings, history, privacy, recovery, and multi-display behavior.

  2. 02

    Validate a trace

    Keep statuses, timing, and evidence codes inside the public contract before sharing them.

  3. 03

    Compare two traces

    Get a parity matrix with bounded deltas and gap descriptions that point to the next useful check.

The useful moment

Activation can feel great while recovery, history, or multi-display behavior quietly falls behind. FlowDiff makes that gap visible before it becomes a debate.

Small input. Strict output.

The validator accepts eight capability events, bounded statuses, and allowlisted evidence codes. Unknown fields fail closed.

{
  "schema_version": "1",
  "app": "Candidate",
  "events": [{
    "capability": "activation",
    "status": "pass",
    "duration_ms": 150,
    "evidence_codes": ["bar_opened"]
  }]
}

What stays out

FlowDiff is deliberately not a recorder or product analytics SDK.

  • Audio and transcripts
  • Screenshots and clipboard contents
  • URLs, paths, credentials, and identifiers
